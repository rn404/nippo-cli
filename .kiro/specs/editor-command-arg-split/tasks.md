# Implementation Plan

- [ ] 1. `$EDITOR`/`$VISUAL` 複数トークン対応の実装とテスト
- [ ] 1.1 エディタ起動処理のトークン分割対応
  - 本番用のエディタ起動処理で、解決済みの `$EDITOR`/`$VISUAL`（または `vi`）の値を空白区切りでトークン化する
  - トークンが2個以上ある場合、先頭トークンを起動コマンド、残りのトークンと編集対象の一時ファイルパスを引数として渡してプロセスを起動する
  - トークンが1個（単一トークンの値）の場合は、これまでと同じくそのトークンのみを起動コマンドとして扱う（引数無し + 一時ファイルパスのみ）
  - トークンが0個（値が空白のみ）の場合は、プロセス起動を試みずにエラーを返す
  - 分割後の起動コマンドが見つからない、または起動時にエラーが発生した場合は、既存通りそのままエラーを返す（自動的な別エディタへのフォールバックは行わない）
  - 複数トークンの値・単一トークンの値・空白のみの値のそれぞれで、起動コマンドと引数の組み立てが期待通りになることを検証するテストを書く
  - 存在しないコマンド名（分割後）を指定した場合にエラーが返ることを検証するテストを書く
  - Observable: `go test ./cmd/sava/...` で新規テストが全てパスし、複数トークン・単一トークン・空白のみの3パターンそれぞれで期待した起動コマンド/引数、またはエラーが得られることが確認できる
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 2.1, 2.2_
  - _Boundary: runEditor_

- [ ] 1.2 複数トークン `$EDITOR` でのエンドツーエンド検証と既存挙動の回帰確認
  - `$EDITOR` を「フェイクスクリプトのパス + ダミー引数」に設定し、`add`（または `edit`）のエディタモードで、フェイクスクリプトがダミー引数付きで正しく起動され、一時ファイルパスが最後の引数として渡ることを検証するエンドツーエンドテストを書く
  - 同様に、別のコマンド（`todo`/`edit` のうち1.2で未検証の方）でも複数トークンの `$EDITOR` が正しく機能することを検証するテストを書き、`add`/`todo`/`edit` すべての経路で一貫して分割対応が適用されることを確認する
  - 既存の単一トークン `$EDITOR` によるエディタモードの統合テスト群を変更せずに実行し、回帰が無いことを確認する
  - Observable: `go test ./cmd/sava/...` で、複数トークンの `$EDITOR` を使う新規エンドツーエンドテストと既存の単一トークンのエディタモードテストの両方が、`add`/`todo`/`edit` すべてでパスする
  - _Requirements: 1.1, 1.2, 3.1_
  - _Boundary: runEditor_
