- [x] 1. Timeline行フォーマットの再実装とユニットテスト
  - `internal/view` のアイテム描画ロジックを、未着手 `- [ ]` / 着手中 `- [ ] \`in-progress\`` / 完了 `- [x]` / メモはチェックボックス無しの4パターンに描画し分けるよう実装する
  - hashを常に行末の `` (`hash`) ``（括弧＋バックティック）に統一し、アイテム種別にかかわらず同一の位置・形式にする
  - タグは既存通りhashトークンの後ろに表示する（表示形式自体は変更しない）
  - contentが複数行のとき、デフォルトでは先頭行のみを表示する先頭行抽出ロジックを実装し、全文表示に切り替えるパラメータを設ける
  - 旧来の4状態マーカー（`・`/`[ ]`/`[>]`/`[x]`）を描画していた既存ロジックは新ロジックに置き換える
  - 既存の単体テストを新しい呼び出し方に追従させ、未着手/着手中/完了/メモそれぞれのチェックリスト構文、hash表記、タグの位置、先頭行要約、全文表示を検証するテストケースを追加する
  - 呼び出し側のシグネチャ変更（新パラメータ追加）により、このタスク単独では `internal/command` がコンパイルできなくなる（`go build ./...`/`go test ./...` はリポジトリ全体では失敗する）。これはタスク2.1で呼び出し側を更新するまでの想定された中間状態であり、不具合ではない。このタスクの検証は `go test ./internal/view/...` というパッケージ単位のコマンドで行う
  - Observable: `go test ./internal/view/...` で新規・既存テストが全てパスし、各状態（未着手/着手中/完了/メモ）のチェックリスト構文とhash表記が期待通りであることが確認できる
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 2.1, 2.2, 2.3, 3.1, 3.2, 4.1, 4.2_

- [ ] 2. FullTextオプションの橋渡しとCLI統合
- [x] 2.1 全文表示オプションのcommand層への橋渡し
  - `list` コマンドのオプションに、全文表示を切り替えるフラグ値を追加する
  - 日次表示（stat無し）で、このフラグ値をタスク1で実装した描画ロジックに渡す（これにより、タスク1の時点で生じていた `internal/command` のビルド不整合が解消され、リポジトリ全体が再びビルド可能になる）
  - stat表示（`-s`）と全ファイル一覧（`-a`、stat無し）の処理では、このフラグ値を一切参照せず、既存の出力をそのまま維持する
  - 複数行のcontentを持つアイテムについて、フラグの有無で出力（先頭行のみ/全文）が切り替わることを検証する統合テストを追加する
  - `-s`/`-a`（stat無し）の出力が、このフラグを渡しても渡さなくても変化しないことを検証するテストを追加する
  - Observable: 複数行メモを持つログに対し、フラグを指定したときだけ全文が出力に含まれ、指定しないときは先頭行のみになる
  - _Requirements: 4.1, 4.2, 5.1, 5.2, 5.3, 5.4_
