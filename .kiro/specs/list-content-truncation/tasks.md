# Implementation Plan

- [x] 1. Core: content要約ロジックの実装と internal/view のユニットテスト更新
  - デフォルト表示・`--full-text`表示の両方で使う、content内の連続する改行（1つ以上のラン）を単一の半角スペースに圧縮するロジックを実装する
  - `--full-text`が指定されていないとき、圧縮後の文字列を先頭から50文字（rune単位）に切り詰め、切り詰めが発生した場合のみ末尾に省略記号「…」を付与するロジックを実装する
  - `--full-text`が指定されているとき、圧縮後の文字列を切り詰めずに全文そのまま使うロジックを実装する
  - 既存の「最初の改行までを1行とする」ヘルパーとその呼び出し箇所を、上記ロジックに置き換える
  - 改行を含み圧縮後50文字以内のcontentが、改行のみ圧縮されそのまま表示され、省略記号が付かないことを検証するテストを追加する
  - 圧縮後50文字を超えるcontentが、先頭50文字+省略記号で表示されることを検証するテストを追加する（ちょうど50文字の境界値ケースを含む）
  - 連続する改行（例: 空行区切りの複数行content）が、スペースの連続ではなく単一の半角スペースに圧縮されることを検証するテストを追加する
  - 圧縮後50文字を超える複数行content（連続改行を含む）に対し、`--full-text`指定時は切り詰め・省略記号なしで全文が表示されることを検証するテストを追加する
  - デフォルト表示・`--full-text`表示いずれの場合も、出力がcontent量に関わらず常に1アイテム=1行であることを検証するテストを追加・維持する
  - 既存の「最初の改行までを切り出すヘルパー」に対する単体テスト、および改行がそのまま残ることを前提にしていた既存の全文表示テストを、新ロジックに対するテストに置き換える（この置き換えを本タスク内で行わないと、同一パッケージ内でテストが新ロジックと矛盾したままになり `go test ./internal/view/...` がビルド・パスできなくなるため、実装とテスト更新を1タスクにまとめている）
  - Observable: `go test ./internal/view/...`が新ロジックの下で全てパスし、日次表示（非stat）のcontent算出が新ロジックを経由する
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 2.1, 2.2, 2.3_
  - _Boundary: view.Timeline_

- [ ] 2. Integration: 既存の呼び出し側・CLI統合テストの回帰対応
- [ ] 2.1 (P) command層の統合テスト更新
  - 複数行かつ圧縮後50文字以内のcontentに対する、非`--full-text`時の期待値を新ロジック（改行圧縮のみが行われ、2行目以降の内容も同一行に表示される）に合わせて更新する
  - `--stat`・`--all`（stat無し）の出力が`FullText`を含む新旧フラグの組み合わせで変化しないことを検証する既存テストが、変更なしにそのままパスすることを確認する
  - キーワードが2行目以降にしか出現しない複数行メモを`FullText: true`で表示したとき、出力中でそのキーワードを含む行が、hashを含むアイテム全体の行であることを検証する統合テストを追加する（`sava list --full-text | grep 'word'`で該当アイテムが1件・1行で確実にヒットするという、このspecの動機を裏付けるE2Eテスト）
  - Observable: `go test ./internal/command/...`が新ロジックの下で全てパスし、キーワードが後方の行にあるケースでもhash付きの1行としてマッチすることが確認できる
  - _Requirements: 1.1, 1.3, 2.1, 2.2, 2.3, 3.1, 3.2, 3.3, 3.4_
  - _Boundary: command.listOneDay (テストのみ)_

- [ ] 2.2 (P) CLI統合テスト更新
  - `--full-text`のCLI統合テストが検証している、改行を含む複数行content出力の期待値（改行がそのまま残ることを前提にしたもの）を、改行が半角スペースに圧縮された期待値に更新する
  - `--full-list`と`--full-text`を組み合わせた統合テストについても、同様に改行圧縮後の期待値に更新する
  - Observable: `go test ./cmd/sava/...`が新ロジックの下で全てパスする
  - _Requirements: 2.1, 2.2, 2.3_
  - _Boundary: cmd.newListCommand (テストのみ)_

- [ ] 3. Validation: リポジトリ全体の回帰確認
  - タスク1・2の変更を反映した状態でテストスイート全体を実行し、新しいcontent要約ロジックの影響で他の既存アサーション（チェックリスト構文・hash表記・タグ位置など）が破綻していないか確認する
  - 破綻するアサーションがあれば、検証している内容自体（どのアイテムが表示されるか、順序、hash/タグの位置等）は変えずに、期待する文字列表現のみを新ロジックに合わせて更新する
  - Observable: `go test ./...`が全パッケージでgreenになる
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 2.1, 2.2, 2.3, 3.1, 3.2, 3.3, 3.4, 3.5_
  - タスク1・2で変更した範囲を横断して再確認する検証専用タスクのため、両方の完了後に着手する（直前タスク群のため暗黙の依存として扱う）
